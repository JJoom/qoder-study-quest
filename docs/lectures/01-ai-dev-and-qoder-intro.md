# 第 01 讲 · AI 编程是什么 + Qoder 初体验

> 本讲不需要任何前置知识。目标只有一个：让你亲手体验一次「和 AI 一起写代码」，并建立正确的心理预期。

## 1. 学习目标与本讲地图

学完本讲，你将能够：

- [ ] 用一句话说清楚 AI 编程是什么、不是什么
- [ ] 打开 Qoder 并找到最常用的几个功能入口
- [ ] 完成第一次「对话写代码 → 运行 → 修改」的完整循环
- [ ] 理解「AI 会犯错」这一核心事实，知道为什么要审查 AI 代码

本讲地图：

```
AI 编程的正确认知 → 认识 Qoder 界面 → 第一次对话实战 → 迭代修改体验 → AI 的局限
```

## 2. 术语表

| 术语 | 一句话理解 |
| --- | --- |
| AI 编程 / AI 辅助开发 | 让 AI 像一个坐你旁边的资深同事，陪你一起写代码、查问题、解释代码 |
| IDE（集成开发环境） | 写代码用的「全家桶」软件，能编辑、运行、调试代码。Qoder 就是一个 IDE |
| 大模型（LLM） | AI 背后的「大脑」，通过海量代码训练出来，能理解和生成自然语言与代码 |
| 提示词（Prompt） | 你对 AI 说的话。说得越清楚，AI 干得越好，就像给新同事交代任务 |
| 对话 / 会话（Chat） | 你和 AI 一问一答的交互窗口，可以连续追问、逐步修改 |
| 迭代 | 不追求一次完美，而是「生成 → 检查 → 提出修改 → 再生成」的循环 |

## 3. AI 编程的正确认知

### 3.1 一个比喻：结对程序员，而不是代码生成器

很多人第一次接触 AI 编程，把它当成「自动贩卖机」：投一句话进去，掉一个完整软件出来。**这是错误预期，也是翻车的根源。**

正确的比喻是：**AI 是你身边一位知识渊博但偶尔粗心的结对程序员**。

- 他懂几乎所有主流语言和框架，你可以问他任何问题
- 他写代码速度极快，但不会主动验证自己的代码能不能跑
- 他有时会「一本正经地胡说八道」（后面会讲，这叫幻觉）
- 他需要你把需求交代清楚——你含糊，他就靠猜

所以 AI 编程的本质是：**你负责想清楚要什么、判断做得对不对；AI 负责高效产出初稿**。你是代码的最终责任人。

### 3.2 AI 编程能干什么（本课程范围内）

| 场景 | 例子 |
| --- | --- |
| 生成代码 | 「写一个用户注册的 REST 接口」 |
| 解释代码 | 「这段 Spring Security 配置在做什么？」 |
| 修改重构 | 「把这个类里的 if-else 改成策略模式」 |
| 排查报错 | 把错误堆栈贴给 AI，让它分析原因 |
| 写测试 | 「给这个 Service 方法写单元测试」 |
| 写文档 | 「给这个接口生成 OpenAPI 注释」 |

## 4. Qoder 能力点讲解：认识你的新工作台

> 下面的界面描述以 Qoder 的通用布局为准。个别按钮位置可能随版本微调，找不到时用界面上的搜索功能。

### 4.1 界面五大区域

打开 Qoder 后，你会看到一个类似 VS Code 的界面（Qoder 基于 VS Code 生态构建，如果你用过 VS Code 会非常熟悉）：

| 区域 | 位置 | 作用 |
| --- | --- | --- |
| 资源管理器 | 左侧栏 | 浏览和打开项目文件 |
| 编辑器 | 中间 | 写代码的主区域 |
| AI 对话面板 | 右侧栏 | 与 AI 对话的核心窗口（本讲主角） |
| 终端 | 底部 | 执行命令行命令 |
| 状态栏 | 最底部 | 分支、语言模式等状态信息 |

### 4.2 与 AI 对话的几种方式

| 方式 | 怎么触发 | 适合场景 |
| --- | --- | --- |
| 对话面板（Chat） | 右侧栏图标或快捷键（常见为 `Ctrl+L` / `Ctrl+I`，以你的版本为准） | 提问、让 AI 生成或修改代码 |
| 行内对话（Inline Chat） | 在编辑器中选中代码后按快捷键 | 针对选中的一小段代码快速提问或修改 |
| @ 引用 | 在对话输入框中输入 `@` | 把某个文件/文件夹作为上下文提供给 AI（第 02 讲详解） |

### 4.3 第一个重要概念：AI 的「模式」先不管，先用起来

你可能听说过 Agent 模式、Ask 模式等名词。**本讲先不解释它们**——先用手感建立认知，概念放到第 02 讲系统讲。本讲所有操作使用默认的对话方式即可。

## 5. 分步实战：你的第一次 AI 编程

> 准备工作：新建一个空文件夹作为练习目录（例如 `qoder-playground`），用 Qoder 打开它。本练习不依赖 Java 环境，用任何语言都行；下面以 Python 为例，没有 Python 也可以让 AI 换成 JavaScript。
>
> Python 环境说明：Windows 需要先在微软商店或 Python 官网（python.org）安装 Python，装完在终端执行 `python --version` 验证。注意：未安装 Python 时在 Windows 终端输入 `python` 会弹出微软商店引导页，这是正常现象，不是报错。

### 步骤 1：让 AI 写一个 Hello World

打开右侧 AI 对话面板，输入你的第一条提示词：

> **提示词示例（可直接复制）：**
>
> ```
> 请创建一个 hello.py 文件，写一个 Python 程序：询问我的名字，然后向我问好。
> ```

**预期产出**：AI 会提议创建一个 `hello.py` 文件，内容大致如下：

```python
name = input("请输入你的名字: ")
print(f"你好, {name}! 很高兴认识你。")
```

**检查要点**：

- AI 会展示它打算做的改动（新建文件 + 文件内容），通常需要你点击「接受/Accept」才会真正写入文件。**认真看一眼内容再接受**——这是全课程最重要的习惯。
- 接受后，左侧资源管理器中应该出现 `hello.py`。

### 步骤 2：运行它

两种方式任选：

1. 在编辑器打开 `hello.py`，点击右上角运行按钮（如果有）
2. 打开底部终端，执行：

```bash
python hello.py
```

**预期产出**：终端提示输入名字，输入后打印问候语。

### 步骤 3：迭代修改——体验对话的连续性

不要开新对话，**在同一个对话里继续说**：

> **提示词示例：**
>
> ```
> 很好。请改进一下：1）如果用户直接回车没输入名字，使用默认称呼"朋友"；2）根据当前时间输出不同的问候语（早上/下午/晚上好）。
> ```

**预期产出**：AI 修改 `hello.py`，增加空输入兜底和时间判断逻辑（会用到 `datetime` 模块）。

**检查要点**：

- 注意 AI 记得之前的上下文——它是在原文件基础上修改，而不是从零重写。这就是「对话连续性」的价值。
- 再次运行验证行为是否符合预期。

### 步骤 4：故意提一个模糊需求，观察 AI 如何应对

> **提示词示例：**
>
> ```
> 再加点功能，弄好看点。
> ```

**预期产出**：AI 会做一些猜测性修改（比如加 ASCII 艺术字、分隔线等）。

**要点体会**：你有没有发现，需求越模糊，AI 的发挥越「随机」？**这就是为什么企业级开发必须把需求写清楚再让 AI 动手**（第 03 讲的主题）。

### 步骤 5：让 AI 解释代码

随便选中文件里的几行代码，在对话中问：

> **提示词示例：**
>
> ```
> 逐行解释这段代码的作用。
> ```

**预期产出**：AI 给出逐行讲解。这是学习陌生代码最快的方式——后面的 Spring Security、JWT 等复杂代码，都可以这样学。

## 6. 常见坑与 AI 幻觉识别（入门版）

### 坑 1：AI 的代码不一定能跑

AI 生成的代码是「看起来正确」的，不是「验证过正确」的。**永远要运行一次再说。**

### 坑 2：AI 会一本正经地胡说八道（幻觉）

幻觉（Hallucination）指 AI 生成看似合理、实则错误的内容。入门阶段最常见的形态：

- 引用不存在的库或函数名
- 编造不存在的配置项
- 解释代码时张冠李戴

**识别方法**：运行验证 + 对「没见过」的 API 去官方文档确认。本课程每讲都会给出具体的检查清单。

### 坑 3：全盘接受不看 diff

AI 的每次修改都要看一眼它到底改了什么。养成习惯：接受前浏览变更内容。

### 坑 4：一次对话塞太多需求

一次让 AI 做一件事。需求越集中，产出质量越高，出了问题也越好定位。

## 7. 课后练习任务

1. **练习 A（基础）**：让 AI 把 `hello.py` 改造成一个「命令行猜数字游戏」：程序随机生成 1-100 的数字，玩家输入猜测，程序提示「大了/小了」，猜对后显示用了几次。
2. **练习 B（迭代）**：在练习 A 的同一对话中，继续让 AI 增加「最多猜 7 次，超过算失败」的规则。体会上下文连续修改。
3. **练习 C（解释）**：把练习 A 生成的完整代码贴给 AI（或选中代码提问），让它解释每一部分，确认你能看懂全部代码。
4. **练习 D（找茬）**：故意问 AI：「Python 里有没有一个叫 `string.reverse()` 的方法？」——实际不存在。观察 AI 是承认没有还是编造答案。这会让你直观感受幻觉。
