# 第 12 讲 · AI 驱动的前端页面开发

> 本讲完成 QShop 全部核心页面。核心技能：给 AI 提供「组件规范 + 一个样板页面」，让它批量产出风格统一的页面——这是前端 AI 开发的第一技巧。

## 1. 学习目标与本讲地图

学完本讲，你将能够：

- [ ] 编写前端组件规范文档并放进 Rules
- [ ] 打磨一个「样板页面」供后续页面参照
- [ ] 完成商品列表/详情、购物车、订单、后台管理等核心页面
- [ ] 用 Pinia store 驱动购物车角标等跨组件状态
- [ ] 识别 AI 前端代码的典型质量问题并纠正

本讲地图：

```
组件规范 → 样板页面 → 商品页 → 购物车页 → 订单页 → 后台管理页
```

## 2. 术语表

| 术语 | 一句话理解 |
| --- | --- |
| 组件规范 | 约定页面怎么写：文件结构、命名、状态管理方式、API 调用方式的书面标准 |
| 样板页面 | 一个精挑细磨的参考页面，后续页面照着它生成 |
| 骨架屏/加载态 | 数据没回来时的占位效果，企业级页面的基本素养 |
| 受控表单 | 表单值全部由 JS 状态驱动，提交前统一校验 |

## 3. 企业级知识点：为什么前端更需要「规范 + 样板」

后端有包结构和类型系统兜底，前端页面的「自由度」大得多——同样一个列表页，AI 可以写出十种风格（有的用 el-table 有的自己写 div，有的 loading 用变量有的用 ref 包装）。**不先定规范就批量生成页面，得到的一定是「风格拼盘」。**

前端组件规范该写什么：

1. 页面文件放 views/，每个页面一个目录（含子组件）
2. 统一使用 `<script setup>` + Composition API
3. 数据请求统一走 src/api/，页面里不出现 axios 直接调用
4. 加载态、空态、错误态三态必须处理
5. 表格必用 el-table + el-pagination，表单必用 el-form + rules 校验
6. 样式用 scoped，全局样式只在指定文件

## 4. 分步实战

### 步骤 1：把组件规范写进 Rules

> **Rules 追加示例（可直接复制）：**
>
> ```markdown
> ## 前端约定（qshop-web）
> - 页面组件使用 <script setup>，页面文件位于 src/views/<模块>/index.vue
> - 接口调用必须通过 src/api/*.js，禁止页面内直接使用 axios
> - 所有异步数据页面必须处理 loading / 空数据 / 请求失败三种状态
> - 列表页统一使用 el-table + el-pagination，分页参数 page/size
> - 表单使用 el-form 并配置 rules 校验，提交按钮加 loading 防重复点击
> - 新页面参照 src/views/products/index.vue 的结构与风格
> ```

### 步骤 2：打磨样板页面——商品列表

> **提示词示例：**
>
> ```
> @src/utils/request.js @src/api/product.js（若无则先创建）
> 实现商品列表页 src/views/products/index.vue 作为前端样板页面：
> - 顶部：关键字搜索框 + 分类筛选（分类来自 GET /api/v1/categories）
> - 主体：商品卡片网格（图片、名称、价格、销量）
> - 底部：el-pagination 分页，参数 page/size 对接后端规范
> - 完整处理 loading、空数据、请求失败三态
> - 卡片点击跳转 /products/:id
> 这是样板页面，请在关键位置写注释说明结构意图。
> ```

**预期产出**：样板列表页 + `src/api/product.js`。

**验证**：看到种子商品分页展示；切换页码、搜索、筛选均正常；断掉后端观察失败态。

**审查标准**（对照组件规范逐条检查）：不合格就继续迭代，直到它配当样板。

### 步骤 3：商品详情页

> **提示词示例：**
>
> ```
> @src/views/products/index.vue 参照样板页面风格实现商品详情页 src/views/product-detail/index.vue：
> 左侧主图、右侧名称/价格/销量/库存、数量选择器（不超过库存）、加入购物车按钮、立即购买按钮
> 加购调用 POST /api/v1/cart/items，成功后顶栏购物车角标 +1；未登录点击加购跳转登录
> ```

**检查要点**：

- 「加入购物车成功」后角标更新是否通过 Pinia 的 cart store 驱动，而不是组件间事件硬传
- 数量为 0、库存不足、商品已下架（404）的边界提示

### 步骤 4：购物车页

> **提示词示例：**
>
> ```
> 实现购物车页 src/views/cart/index.vue：
> - el-table 展示：勾选框、图片、名称、单价、数量步进器（数量改动即时调 PUT）、小计、删除
> - 底部结算栏：已选件数、合计金额（BigDecimal 精度问题用分为单位或 toFixed(2) 谨慎处理）
> - 结算按钮：未勾选时禁用；点击跳转订单确认页（携带已选 productId 列表）
> - 页面数据来自 GET /api/v1/cart，并更新 Pinia cart store 驱动角标
> ```

**检查要点**：金额显示是否出现 `0.30000000000000004` 这类浮点瑕疵——有就要求修正（前端展示层用字符串处理或整数分）。

### 步骤 5：订单确认页 + 我的订单

> **提示词示例：**
>
> ```
> 1. 订单确认页 src/views/order-confirm/index.vue：地址选择（来自 GET /api/v1/addresses，支持选默认地址）、
>    已选商品清单、应付金额、提交订单（调 POST /api/v1/orders）；无地址时展示引导文案并提供
>    「新增地址」弹窗表单（el-dialog + el-form，对接 POST /api/v1/addresses，保存后自动选中新地址）
> 2. 提交成功跳转「支付提示页」：展示订单号与"去支付"按钮（调 POST /api/v1/payments 后调模拟回调接口，
>    支付成功展示成功页）
> 3. 我的订单页 src/views/orders/index.vue：订单列表（el-table + 状态标签 + 分页 + 状态筛选）、
>    详情抽屉（订单明细+收货信息）、待支付订单显示"取消订单"与"去支付"操作
> ```

**验证**：完整走一遍「加购 → 购物车 → 结算 → 支付 → 订单列表见已支付」，这是 QShop 的主干用户旅程。

### 步骤 6：后台管理页

> **提示词示例：**
>
> ```
> @src/views/products/index.vue 参照样板实现后台三个管理页：
> 1. /admin/products：商品列表（含下架商品与状态列）、新增/编辑弹窗表单（el-dialog + el-form，
>    主图用上传组件对接 /api/v1/admin/upload）、上下架与删除操作带确认框
> 2. /admin/categories：分类管理（简单表格 CRUD）
> 3. /admin/users：用户列表、启用/禁用开关
> 所有写操作成功后刷新列表并 ElMessage 提示。
> ```

**检查要点**：

- 编辑弹窗提交的是完整表单还是只提交变更字段（与后端 PUT 语义对齐）
- 删除/下架均有 el-popconfirm 或 ElMessageBox 确认，防止误操作
- 表单校验规则与后端 DTO 校验一致（名称必填、价格>0）

## 5. 常见坑与 AI 幻觉识别

1. **风格漂移**：第 5、6 个页面开始 AI 可能忘记样板约定。对策：每次生成提示词都显式 @ 引用样板页面。
2. **三态缺失**：只有「数据正常」一条路，loading/空/失败态缺失。用「规范 + 断网实测」双保险检查。
3. **API 层被绕过**：页面里出现 `import axios from 'axios'`，违反规范，驳回。
4. **响应式丢响应**：把响应式对象解构赋值（`const { data } = await api()` 后又整体替换对象）导致视图不更新——运行验证每个交互。
5. **Element Plus 组件 API 幻觉**：AI 可能用旧版属性名（如 el-table 的某些 prop）。页面渲染异常时，先看控制台报错，再对照 Element Plus 官方文档确认属性名。
